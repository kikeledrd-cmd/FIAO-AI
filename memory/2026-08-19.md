- **Dominio** `domain/ai/ai-intent.ts`: `parseAiIntent` determinístico (español/dominicano) que clasifica QUERY vs ACTION y extrae monto/customerQuery; matching por **palabra completa** (word boundary) para que "venta" no matchee dentro de "inventario"; `extractAmountCents` (RD$ / pesos / "con N"), `detectAnomalousAmount`, labels `CONFIRMED|ESTIMATED|RECOMMENDATION`. La ambigüedad de entidades nunca se auto-resuelve. 17 tests.
- **Contratos** `contracts/ai.ts` + **migración** `commerce_ai` (`AiAuditLog` append-only + `AiActionToken` de un solo uso con TTL).
- **Repos** `AiQueryRepository` (agregaciones read-only: ventas, fiado, saldo de cliente, inventario bajo, caja, pedidos; reutiliza `computeExpectedCashForSession`) y `AiAuditRepository` (log + tokens).
- **Tool registry** `database/ai/tools.ts`: `runAiQuery`, `buildActionPlan` (resuelve cliente por nombre con ambigüedad, ids estables para replay), `executeActionPlan` → `processOperation`. Acciones: abono y apertura de caja con confirmación; ajuste de stock protegido (PIN); venta/pedido → "hacerlo desde la UI" en V1.
- **Orquestador** `apps/web/lib/ai/orchestrator.ts` + `provider.ts` (adapter mockeable; el modelo SOLO produce intents). `handleMessage` + `confirmAction` con audit log.
- **API/UI**: `POST /api/ai/message`, `POST /api/ai/confirm`; pantalla `/ai` (chat + voz Web Speech + confirmación + PIN); card FIAO AI en home.

### Gotchas nuevos

- **Docker Desktop se apaga entre sesiones** (Postgres 5433 cayó con `ECONNREFUSED` a mitad de la tarea); reiniciar con `Start-Process "C:\Program Files\Docker\Docker\Docker Desktop.exe"` + `docker compose up -d` y esperar antes de testear.
- `AiActionToken.tokenId` se genera en el código (no tiene `@default` en Prisma); el `payload` se castea a `Prisma.InputJsonValue`.
- Los payloads usan el **`customerId` público**, pero `CreditMovement.customerId` es FK al `id` interno → resolver cliente antes de consultar saldo.
- Los overrides null del handler de API **no deben pisar** el monto extraído del intent (fusionar ignorando null); si no, "abona 500" se convertía en monto 0.
- El E2E de "abrir caja" chocaba con `CASH_SESSION_ALREADY_OPEN` (cash-flow.spec abre caja antes) → usar "abona X a <cliente>" para la acción con confirmación (no depende de estado global).
